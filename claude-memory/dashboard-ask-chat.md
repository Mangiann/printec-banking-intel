Built 16/09/2026 at the user's request ("a chat for querying whatever the user wants to know about the presented data"). Decision path: proposal → clarified that no API is used (the page asks Claude through the claude.ai viewer on the viewer's own account; on Enterprise it runs on Enterprise seats) → user chose to test on the personal artifact first, then publish the same file from the Enterprise account.

**Where it lives:** `weekly-intelligence/scripts/artifact/patch_artifact.py` has `ASK_JS` (the chat) and `ASK_CSS`; `build_artifact.py` inserts ASK_JS *inside* app.js's closing IIFE (app.js is wrapped in `(function(){ ... })();`, so appending after it cannot see `DASH`, `sigByKey`, `mdToHtml`, `current`) and adds ASK_CSS to the style block. Vercel/dashboard-web is untouched. The publish must declare `capabilities: {sample: {}}` (done on artifact v66).

**How it works:** `claude.use('sample')` → if null (outside the claude.ai viewer, e.g. the local test build) the button never appears; `window.__askDebug={factSheet, tools, buildInput, renderAnswer}` is exposed for local testing. Each question = ONE user turn: instructions + a fact sheet (~15k chars: week, KPIs, markets, lines, 14 largest opportunities, 12 deadlines, competition brief, futures titles, and when the Admin view is unlocked the budget totals/by-market/by-line/executive summary; plus the current tab and any open cell/signal) + the last 3 Q/A + the question. Ten tools (page functions) as of 17/09/2026: search_signals, get_signal, get_market, get_product_line, get_competitor, list_deadlines, get_budget_line (throws while locked), get_outlook, list_moves (lines by move / market, added 16/09 after the user saw the chat offer to look up protect-margin lines instead of listing them), get_budget_categories (HW/SW/SV/OUT split, also locked-gated, added with [[budget-by-category]]; prefetch fires it on category/waterfall/hw/sw/sv/out words). Results ≤ ~5 KB. The fact sheet and glossary now also carry the category split and the drivers/levers. Answers cite `[signal-key]`; the page strips them, drops the "Sources:" line and renders evidence chips (`.ol-builton .ol-sig` → existing revealSignal). Suggested questions per tab. Errors: not_granted hides the button, rate_limited message, tools_unavailable retries without tools, cancelled keeps partial text. `modelTier: default`; with tools no `cache` option; without tools `cache:false`.

**Feedback 16/09/2026:** the chat could not explain the page's own columns/labels ("I can't verify exact labels"). Fixed by adding `glossary()` to every question: the tabs (from TABS), signal lanes/bands/recency chips, outlook rules, the Budget tab top to bottom (estimate cards, the reference line, the moves grid, the moves legend, the drill-down, the "Retail and other, carried flat" column), the model's growth rules, views and delivery checks; plus an instruction to answer page questions directly from it. Keep the glossary in step with UI changes (it is prose in patch_artifact.py). The "Not covered" column was relabelled "Retail and other, carried flat" with a hover note and the retail/other split (v68).

**Test of 16/09/2026:** 17 questions run offline with `askrun.js` (scratchpad; rebuild from patch_artifact ASK_JS + app.js pieces: it evaluates buildInput/tools on the real data, `node askrun.js preamble|tools|tool`) by sonnet agents acting as the chat. Result: figures correct in 17/17; tool choice sensible (0–6 calls); honesty traps passed. Weak spots fixed in the prompt: "guaranteed floor" wording, too-terse answers to "difference between" questions, dashes/contractions/symbols, and the budget tool now returns plan_adds_to_budget/floor and floor_includes_closing_fact so the Greek/Romanian/Bulgarian floors are explained. One unsupported claim seen (Brink's competing "in Greece"): the rule against invention is in the prompt; watch for it. Artifact v70.

**Prefetch (16/09/2026, v73):** the live model ("default" tier) twice answered the protect-margin question with the definition and an OFFER to look up the lines instead of calling `list_moves`. Fix: `prefetch(q)` in ASK_JS runs the obvious tools page-side before asking (a named move → list_moves; a market name → get_market + get_budget_line when unlocked; a competitor name → get_competitor; a line word → get_product_line; deadline words → list_deadlines; always the 5 closest signals) and puts the results in a "DATA THE PAGE FETCHED FOR THIS QUESTION" block; INSTR now forbids offering to look things up. Prompts run 29–42 KB, under the 64 KB cap. The panel's subtitle shows the build stamp so the pinned version can be checked.

**v74 (16/09/2026 18:09):** three fixes from the live test. (1) The PrivatBank status answer missed the key fact that it is not known whether Printec passed stage 1, because the prefetch only sent title/date/implication briefs: `search_signals` now weights query words by rarity (1/(1+ln df); "status", "tender" no longer outrank "PrivatBank") and prefetch adds the full `get_signal` of the first top-5 match whose title shares a distinctive word (≥5 letters, stoplist) with the question. (2) The Romania growth answer called the other four fetched lines "not itemised": INSTR now says account for every fetched line and report status questions from the full text incl. what is not yet known. (3) The panel subtitle shows `modelTierApplied` after each answer ("answered by the default model tier"); the chat asks for tier "default" (balanced everyday model; "complex"/"quick" are the alternatives; the platform may substitute a cheaper tier the viewer's plan has). Cost (user asked 16/09 to keep it low): no bill; each request spends the viewer’s own usage; v75 adds the rule "at most two tool calls per question, none when the fetched data answers"; prefetch is free page-side JS and exists to avoid tool rounds; prompt 29–42 KB (~8–10k tokens) per request, one request plus one per tool round; tool calls are never cached.

**Limits to remember:** maxPromptBytes 65,536 (fact sheet clipped at 24k chars); each tool round is a paid request on the viewer's account; a handful of rounds max. The artifact-view pane in the desktop app is read-only for me — I cannot type into the chat; the user tests it live.
