Assessment (2026-07-28, read-only, no files changed) of how to combine two local projects:
- Deterministic chatbot at `/Users/mangian/POS paper roll order` (see [[pos-paper-roll-order-project]]) — TS/Fastify, port 3000, 25-state persisted FSM, TID+serial+terminal-model+VIP+15-day rules, mock registry/FSM, Vitest 90. Already exposes a programmatic driver: `POST /simulator/api/message` returns `{messages, dev.state}`.
- Foundry AI app at `/Users/mangian/Downloads/merchant-assistant-v2` — Python 3.13/FastAPI, port 8000, Azure AI Projects SDK + OpenAI Responses API, Foundry Prompt Agent (gpt-5-mini), AzureCliCredential, tool-calling loop, SQLite transcript, pytest ~43. No Docker. No inbound sensitive-input scrubbing (gap).

**Key finding:** the two are OVERLAPPING but DIVERGENT implementations of paper-roll ordering. AI app uses a POS-ID model (no VIP/15-day/serial-match/terminal registry); deterministic uses TID+serial. Not "add AI to chatbot" — two parallel implementations.

**Chosen architecture: Option C.** Keep both apps independently runnable. Deterministic engine = single source of truth. Add controlled `POST /internal/v1/conversations|/messages|/actions`, `GET /internal/v1/conversations/{id}` (thin adapter over ConversationService, Zod-validated, service-token auth). AI tools become pass-through to that API. TID/serial/phone go straight to deterministic validators, never into LLM history; model sees only safe events like `{event:"TERMINAL_VALIDATED", registeredModel:"Verifone V240m"}`. `create_fsm_request` NOT exposed to AI. Sensitive-input detector runs BEFORE any text reaches the model. Create a thin third project `/Users/mangian/merchant-chatbot-demo` (demo-launcher :4000, shared-contracts OpenAPI, optional gateway, docker-compose) — NO copied source trees.

**User decision (2026-07-28):** align the AI conversation to the deterministic domain model — re-script AI to TID+serial+model+VIP+15-day and delegate all decisions to /internal/v1; retire the AI's POS-ID OrderService (transcript-only).
