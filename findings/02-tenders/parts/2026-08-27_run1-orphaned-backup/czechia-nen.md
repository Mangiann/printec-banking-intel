## Access issues

ezak.cnb.cz: /verejne-zakazky and /zakazky return 404/301; the working GET route is https://ezak.cnb.cz/contract_index.html with ?page=N pagination — confirmed with a desktop Chrome User-Agent. E-ZAK contract detail pages do NOT publish the winning supplier or the contract value for any phase, including 'Zadáno' (awarded); values had to be recovered from the parallel TED notice (this is how the ČNB manipulační-technika per-lot figures were obtained). nen.nipez.cz: the documented p:vz: filter path works for GET keyword search (e.g. /verejne-zakazky/p:vz:nazev=HSM); a plain ?nazev= query string is silently IGNORED and returns the unfiltered default list of 50 — a trap that would produce false negatives. Result sets are capped at 50 rows per query with no visible pagination control, so high-frequency terms (pokladn, trezor, platebn, terminál) are truncated; narrower terms were used to compensate. smlouvy.gov.cz (Czech contracts register, used to try to recover the ČNB HSM winner that E-ZAK withholds): the quick search ignores subject_idnum and returns the unfiltered 4,762-row list; the advanced search returns HTTP 500 on a GET with the documented parameter names and appears to require a POST with a session token. Not solved this run — logged rather than dropped. TED API v3: some field names (winner-decision-date, description-lot, estimated-value-lot) are rejected with HTTP 400; the reliable route is a minimal field list for discovery, then fetching the canonical https://ted.europa.eu/en/notice/{id}/xml and parsing UBL locally. WebFetch on TED /pdf routes returned hallucinated or empty content for two notices (504116-2026 came back describing a vehicle purchase); the /xml route was used instead and is authoritative. pdftotext is not installed on this machine. tenderarena.cz was NOT retried — the brief already records it as returning only a 1.5 KB JSF shell; the TED buyer-scoped query on 'Česká pošta' was used instead, per the proven route, and yielded 412 notices.
