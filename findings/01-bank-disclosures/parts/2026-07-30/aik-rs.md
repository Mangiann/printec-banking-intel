## Access issues

1) printecgroup.com returned HTTP 403 to the fetch tool; resolved by retrying the same URL with a desktop-browser User-Agent via curl. 2) aikbank.rs serves its PDFs gzip-encoded with a .pdf extension, so pdfminer failed with 'No /Root object' until the file was gunzipped — worth remembering for future AikBank runs. 3) zse.hr/en/issuer/166 returns 404; the working primary path for Podravska banka is https://zse.hr/hr/papir/310?isin=HRPDBARA0008. 4) www.nbs.rs served fine once a desktop User-Agent was used; its legacy .xls statistics files (broj_i_promet_bankomati.xls etc.) are BIFF format and unreadable with openpyxl, but the parallel .xlsx files under /statistika/el_novac/ carry the same series and were used instead. 5) NOT SOLVED — AikBank's branch/ATM locator at https://www.aikbank.rs/lokacije/ is an Adobe AEM edge-delivery JavaScript app; /lokacije.json, /lokacije/lokacije.json, /lokacije/locations.json and /query-index.json all return 404 and scripts.js exposes no data endpoint, so the ATM estate could not be enumerated machine-readably. Escalation to a browser session was not attempted this run and is the logical next step. 6) The AikBank news article pages render their body server-side but only on the exact trailing-slash URL; a first pass with a different UA string returned empty bodies and was retried successfully.
